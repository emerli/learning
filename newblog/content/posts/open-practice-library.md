## Flow di Raccolta Requisiti

La sequenza consigliata per la fase di Discover/raccolta requisiti:

```
Start At The End → definisci il risultato atteso
        ↓
Domain Storytelling → racconti il dominio col business
        ↓
Event Storming → scopri gli eventi del processo
        ↓
Event Modeling → modelli il sistema event-driven
        ↓
How Might We → generi soluzioni creative per i problemi emersi
```

| Practice | A cosa serve | Metodo |
|----------|-------------|--------|
| **Start At The End** | Definire il successo prima di iniziare | Si descrive il risultato atteso e si lavora a ritroso |
| **Domain Storytelling** | Imparare il linguaggio del dominio | Si raccontano storie del processo business con sentence diagram |
| **Event Storming** | Scoprire il processo business | Biglietti colorati su un muro, timeline degli eventi |
| **Event Modeling** | Modellare sistemi event-driven | Diagramma timeline + eventi + view/projection |
| **How Might We** | Trasformare insight in domande creative | Domande "Come potremmo..." per generare soluzioni |

### Il funnel del Discover

Il dominio è solo un pezzo. Il Discover è un funnel completo:

**Problema → Utenti → Dominio → Visione → Ideazione**

Saltare il problema = costruire la cosa sbagliata.
Saltare gli utenti = costruire per nessuno.
Saltare la visione = non sapere dove andare.

| Area | Domanda chiave | Practice principali |
|------|---------------|-------------------|
| **Problema** | Qual è il problema? | Start At The End, Abstraction Laddering, Dominating Forces |
| **Utenti** | Per chi lo risolviamo? | Empathy Mapping, User Persona, Jobs to be Done, Emotional Journey |
| **Dominio** | Come funziona il business? | Domain Storytelling, Event Storming, Event Modeling, Impact Mapping |
| **Visione** | Dove vogliamo andare? | Lean Value Tree, OKRs, North Star, Vision Statement, BHAGs |
| **Ideazione** | Come potremmo risolvere? | How Might We, Crazy 8s, Design Sprint, Idea Cyclone |

## Example of Flow End-to-End

Un flow tipico che attraversa tutto il Mobius Loop:

```
─── DISCOVER ───

START AT THE END
  "Fra 6 mesi consideriamo un successo se..."
        ↓
EMPATHY MAPPING
  "Chi sono gli utenti e cosa provano?"
        ↓
DOMAIN STORYTELLING / EVENT STORMING
  "Come funziona il processo business oggi?"
        ↓
IMPACT MAPPING
  "Quali deliverable ci portano al risultato?"
        ↓
HOW MIGHT WE
  "Come potremmo risolvere i problemi emersi?"

─── DECIDE ───

MoSCoW / USER STORY MAPPING
  "Cosa facciamo prima? Cosa può aspettare?"
        ↓
LEAN INCEPTION / MVP
  "Qual è il minimo che ci valida l'ipotesi?"

─── DELIVER ───

SPRINT PLANNING → CI/CD → DEPLOY → MISURARE → RETROSPETTIVA
```

Non è rigido: se il problema non è chiaro, si torna indietro. Il Mobius Loop è iterativo, si può ripercorrere qualsiasi fase.

## Design Sprint - Jake Knapp

Il Design Sprint (libro "Sprint" di Jake Knapp) comprime il Mobius Loop in 5 giorni. È un acceleratore di decisioni: il vincolo di tempo forza la priorità sul core business, niente fronzoli.

```
Day 1 - MAP     → Start At The End + Empathy Mapping
                   "Qual è l'obiettivo? Chi è l'utente?"

Day 2 - SKETCH  → Crazy 8s + How Might We
                   "Come potremmo risolvere? Schizzi veloci"

Day 3 - DECIDE  → Dot Voting + MoSCoW
                   "Quale soluzione scegliamo? Votiamo"

Day 4 - PROTO   → Prototipo interattivo
                   "Costruiamo il minimo per testare"

Day 5 - TEST    → Guerilla Testing / Usability Testing
                   "5 utenti testano il prototipo"
```

Perché funziona:
- **Non puoi perderti in dettagli** → hai un timer che scorre
- **Devi scegliere** → Dot Voting taglia le alternative
- **Devi prototipare il minimo** → solo il core business
- **Devi validare** → 5 utenti il giorno 5, niente survey indefinite

Il prototipo è finto ma il learning è vero. Prende Discover → Decide → Deliver e lo comprime in una settimana.

## Come scegliere le practice

Non esiste un percorso fisso. Le practice si scelgono in base al contesto del cliente:

| Contesto clienti | Practice consigliate |
|------------------|---------------------|
| Business-oriented | Impact Mapping + Lean Value Tree + Start At The End |
| Non sa cosa vuole | Empathy Mapping + Jobs to be Done + How Might We |
| Dominio complesso | Domain Storytelling + Event Storming + Event Modeling |
| Vuole velocemente un Prototipo | Design Sprint (5 giorni, tutto compresso) |
| Challenge chiara | User Story Mapping + MoSCoW e vai |

È come i pattern GoF: non li usi tutti, scegli quelli che risolvono il problema che hai davanti. Il Mobius Loop ti dice **dove** sei, le practice ti dicono **come** muoverti da lì.
